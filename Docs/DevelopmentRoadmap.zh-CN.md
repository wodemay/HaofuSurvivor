# 开发路线与待开发逻辑

本文是当前项目的开发待办总览。现有架构、已完成逻辑、脚本级调用关系分别见 `GameArchitecture.zh-CN.md`、`GameLogic.zh-CN.md` 与 `Scripts/ScriptReference.zh-CN.md`。当对话内容过长被客户端折叠或替换时，直接阅读本文和 `Assets/AGENTS.md` 即可恢复下一步开发上下文。

## 已完成基础

- 角色选择、PlayerRoot 创建、角色内容挂载、相机跟随、血条刷新。
- 统一局内计时、时间阶段倍率、暂停与升级选择冻结。
- 敌人场外生成、追击、生命、死亡、EnemyRoot 对象池。
- 共用 Combat 架构：碰撞攻击、投射物攻击、冷却、阵营判定、通用伤害入口。
- 经验球掉落、持久捕获吸取、经验升级、升级选择队列。
- 武器运行时容器、投射物武器的 1–5 级升级、进化为不可升级武器。

## 近期：完成一局游戏闭环

### 1. 死亡、失败、重开

- 玩家生命归零后进入 `RunPhase.Defeat`。
- 显示失败/结算界面，展示生存时间、等级、击杀数等局内统计。
- 提供重新开始和返回角色选择/主菜单。
- 退出时回收敌人、投射物、经验球，清空攻击与升级队列，销毁 PlayerRoot。

依赖：需要用户创建失败/结算 UI；代码应以 `RunSystem.EndWithDefeat()`、`RunEndedEvent`、`ExitToCharacterSelection()` 为入口扩展。

### 2. 胜利与正式结算

- 确定胜利条件，例如生存至指定时间或击杀 Boss。
- 进入 `RunPhase.Victory`，停止统一时间并显示结算。
- 保存本局统计，为局外奖励提供数据。

依赖：`RunSystem.EndWithVictory()` 已有入口，尚无胜利触发规则、统计模型和 UI。

### 3. 正式返回流程

- 当前 HUD 的返回按钮直接退出到角色选择，只是临时方案。
- 后续应接入主菜单、局外大厅或结算面板，再决定是否重开/返回选择。

## 核心成长：技能与升级池

### 4. 主动技能与闪避

- `SkillGroupConfig.StartingSkillIds` 和 `StartingDodgeId` 已预留，尚未有实际执行系统。
- 实现主动技能冷却、释放输入/自动释放、技能攻击或效果。
- 实现闪避位移、冷却、无敌或碰撞规则。

建议：技能和闪避都作为独立运行时容器；其中造成伤害的行为继续接入 Attack Executor 架构。

### 5. 局内获得新武器和新技能

- 当前升级候选只会升级已经拥有的 WeaponRuntime。
- 增加“装备新武器”“获得新技能”“升级闪避”等候选类型。
- 为角色设置武器/技能槽位上限、重复获取规则和候选权重。

依赖：扩展 `LevelUpModel`、`LevelUpSystem`、PlayerLoadout 数据；升级 UI 层级由用户创建或调整。

### 6. 更完整的升级选择

- 多选项数量配置。
- 候选随机权重、刷新、跳过、保底规则。
- 不同武器/技能的专属升级路径。
- 进化前置条件，例如另一武器、被动属性或等级要求。

## 战斗与敌人内容

### 7. 更多攻击形式

- 敌人远程投射物、扇形弹幕、范围爆炸、持续射线、召唤、冲刺、环绕、陷阱等。
- Boss 可通过 `EnemyConfig.AttackIds` 同时挂载多个 Attack ID。
- 每种新攻击行为添加独立 `ExecutorId`；共用 AttackSystem、DamageSystem、RunTimerSystem 和阵营规则。

使用 `.codex/skills/attack-development/`：之后只需描述攻击形式，即可按现有架构接入。

### 8. 敌人行为与状态

- 不同敌人移动策略：保持距离、绕行、冲刺、停驻射击、分裂等。
- 击退、减速、眩晕、无敌、死亡动画等状态系统。
- Boss 生命周期、多阶段技能和时间轴事件。
- 敌人生成规则从当前通用增长扩展为按时间阶段、敌人类型、权重和上限配置。

### 9. 命中与战斗反馈

- 受击闪白、击退、伤害飘字、屏幕震动、音效、特效。
- 投射物/范围攻击的命中特效与死亡表现。
- 这些表现不应绕过 DamageSystem，也必须受统一时间暂停控制。

## 掉落与资源

### 10. 掉落表

- 当前敌人直接引用 `ExperienceDropConfig`，`DropTableId = 0` 仅为预留字段。
- 实现掉落表 Catalog、概率、权重、多个掉落物和不同敌人的掉落方案。
- 经验球可扩展为不同价值、不同吸取表现；也可扩展金币、材料、临时道具。

### 11. 局内统计

- 击杀数、伤害、承伤、武器伤害、技能使用、获得经验、存活时间。
- 统计模型应由 System 写入，结算 UI 通过 Query 读取。

## 局外与内容生产

### 12. 局外系统

- 角色解锁、武器/技能解锁、成就、任务、收藏/图鉴。
- 货币、材料、局外升级、存档版本迁移。
- 正式主菜单和角色选择前的局外大厅。

### 13. 平台与输入

- 移动端虚拟摇杆、触屏按钮、手柄、输入重绑定。
- 自动瞄准策略、震动、分辨率与安全区适配。

### 14. 内容与表现资产

- 正式角色、敌人、Boss、美术 Prefab、动画、音频和特效。
- 用户负责创建/调整 UI、Prefab 层级和 Bind；代码接入须在用户确认后进行。

## 工程质量

### 15. 自动化验证与性能

- Unity Test Framework：优先覆盖 Commands、Queries、Systems。
- Play Mode：验证开局、暂停、对象池复用、死亡/重开、升级选择。
- 性能监控：敌人/投射物/经验球池容量、活跃数量、GC 分配。
- 配置校验：重复 ID、空 Prefab、缺失 Executor、无效进化目标、无效攻击引用。

## 建议开发顺序

1. 死亡 → 失败结算 → 重开/返回，完成完整对局闭环。
2. 新武器获取与升级候选池，使成长具备选择空间。
3. 主动技能与闪避，补全 SkillGroup 预留接口。
4. 第二种敌人攻击和第一只 Boss，验证多 Attack ID 与多阶段行为。
5. 掉落表、局内统计、胜利条件与正式结算。
6. 局外解锁/养成、内容生产、移动端输入和自动化测试。
