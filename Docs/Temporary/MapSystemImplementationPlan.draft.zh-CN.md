# 完整地图系统实施计划（临时）

## 目标

将当前“玩家周围铺设纯地面区块”的原型升级为：先铺满底层地面，再从配置好的树木、墙体、祭坛等阻挡物形状中确定性随机抽取并投放的无限地图。

阻挡物必须经过连通性校验：不能与其他阻挡物围出封闭空间、把玩家困住，或切断当前可探索区域。区块只负责分批生成、显示、卸载和重载，不再承担“固定四向出口”的设计职责。

本计划不实现地图道具、地图事件、世界箭头和 Boss 内容；这些系统后续仅使用地图提供的世界坐标、区块状态和稳定实体 ID。

架构图：`Docs/Temporary/MapSystemArchitecture.draft.drawio`。

## 总体约束

- 每局生成内部 `WorldSeed`，玩家不可见；继续游戏时从快照恢复。
- 基础地图由 `WorldSeed + GeneratorVersion + ChunkCoordinate` 确定性重建，不保存基础 Tile 或 Unity 对象。
- 一块地图先得到完整地面，再生成阻挡物候选，最后通过连通性算法决定哪些候选真正落地。
- 所有地图随机使用确定性哈希随机，不使用 `UnityEngine.Random`。
- 障碍判定使用逻辑格，不依赖 Tilemap、Collider 或 Prefab 是否已加载。
- 阻挡物不可破坏、不可交互，基础地图不需要保存区块增量。
- 地图只负责世界数据、区块流式加载、地形阻挡和导航数据；道具、事件、箭头由独立模块维护自身业务状态。
- 一切运行期更新继续由 `GameLoopSystem` 调度，暂停、升级选择、死亡和结算期间不推进地图逻辑。

## 任务拆解

### 任务 0：冻结地图数据契约

**目的**：先定义稳定的数据边界，避免后续生成、存档、表现和寻路互相引用 Unity 对象。

**新增内容**：

- `WorldMapModel`：`WorldSeed`、固定 `ThemeId`、`GeneratorVersion` 和当前活动区块集合。
- `MapChunkData`：区块坐标、地面格、装饰格、阻挡格、阻挡物投放结果和静态实体锚点。
- `MapObstaclePlacementData`：模板 ID、世界格坐标、旋转/镜像结果、稳定实例 ID。
- `MapCellFlags`：可通行、阻挡移动、阻挡投射物、保留标记。
- `MapGenerationConfig`：区块尺寸、出生点保留范围、候选密度、校验缓冲区尺寸、重试次数和主题配置。

**验收**：同一 Seed、版本和区块坐标在任意加载顺序下得到字节等价的 `MapChunkData`。

**依赖**：无。

### 任务 1：地面铺设与确定性阻挡候选生成

**目的**：先完成“地面永远铺满，障碍只是其上的附加内容”的生成基础。

**实现**：

1. 按区块格坐标铺设基础 Ground，不生成任何移动阻挡。
2. 根据世界坐标哈希、主题权重和模板约束，为每个区块生成稳定的阻挡物候选列表。
3. 候选只描述“可能放什么、放在哪里、如何旋转”，尚未写入阻挡格。
4. 玩家出生格及其相邻八格标记为保留格，候选不得覆盖；其他区域正常生成阻挡物。
5. 跨区块模板以世界坐标作为归属和实例 ID，避免边界重复生成。

**验收**：同一 Seed 重载后地面、候选模板、位置和朝向一致；出生格及其相邻八格始终可通行。

**依赖**：任务 0。

### 任务 2：阻挡物投放与防封闭连通性算法

**目的**：让树木、墙体、祭坛等阻挡物随机出现，但永远不能围出封闭牢笼或把可探索地图切断。

**实现**：

1. 按稳定的全局优先级处理候选，候选处理结果不依赖玩家到达顺序。
2. 将候选形状写入“校验缓冲区”的逻辑格；缓冲区包含目标区块及其周围一圈邻居，用于处理跨区块组合。
3. 每次尝试投放后，对可通行格执行 Flood Fill：所有非阻挡区域都必须能连到校验缓冲区边界，出生安全区还必须保有足够大的可达区域。
4. 若本次投放让多个阻挡物构成闭环、制造孤岛、封住出生区或切断现有通路，撤销本候选，不生成该阻挡物。
5. 达到密度或重试上限时停止投放；不以“硬塞满障碍物”为目标，优先保证路线可走。
6. 对动态破坏/开启后的格子变化复用同一校验接口，保证后续玩法不会写出非法地图状态。

**验收**：大量 Seed 扫描中，任意加载范围内不存在被阻挡物完全围住的可通行孤岛；玩家出生区域始终可以向外移动；加载相邻区块前后不会改变已经确认的障碍结果。

**依赖**：任务 1。

### 任务 3：区块数据与 Unity 表现分离

**目的**：将现有 `MapSystem` 的数据决策、加载队列和 `MapChunkView` 的 Tilemap 表现拆开。

**重构内容**：

- `MapChunkGenerationSystem`：只生成或读取 `MapChunkData`，包含地面、候选和连通性验证结果。
- `MapChunkStreamingSystem`：根据玩家区块决定加载、卸载和预热队列。
- `MapChunkFactory` / `MapChunkView`：只负责对象池、Tilemap 写入和回收。
- `MapChunkView` 只根据 `MapChunkData` 写入表现，不再自行推导随机内容或阻挡规则。

**验收**：同一份 `MapChunkData` 可以被释放并重新加载，地面、障碍视觉和阻挡格保持一致；开局预热仍没有地面闪烁。

**依赖**：任务 0、任务 1、任务 2。

### 任务 4：四层 Tilemap 与物理阻挡

**目的**：把视觉、角色移动和投射物阻挡分离。

**MapChunkRoot 目标结构**：

```text
MapChunkRoot
├─ Grid
│  ├─ GroundTilemap
│  ├─ DecorationTilemap
│  ├─ MoveBlockerTilemap
│  └─ ProjectileBlockerTilemap
└─ Static Rigidbody2D + CompositeCollider2D
```

**规则**：

- Ground：`MapBackground`。
- Decoration：`MapDecoration`。
- MoveBlocker：玩家、敌人的物理阻挡。
- ProjectileBlocker：投射物单独命中的阻挡层。
- 同一障碍模板可只阻挡移动、只阻挡投射物，或同时阻挡两者。

**验收**：角色不会穿过移动阻挡；子弹只在配置要求时被地图拦截；地表和装饰不覆盖战斗单位。

**依赖**：任务 2、任务 3；需要管理员先创建或调整 `MapChunkRoot` 的 Tilemap 和 Collider 结构。

### 任务 5：2D NavMesh 连续寻路与敌人局部避让

**目的**：替换敌人直线追踪，支持障碍物环境下的大量敌人追击。

**实现**：

1. `MapNavMeshSystem` 将活动区块的地面和移动阻挡 Tilemap 构建成 2D NavMesh；投射物阻挡层不参与寻路。
2. 每只敌人只在目标明显移动、区块更新、路径走完或卡住时调用一次 A*，并缓存连续拐点路径。
3. `EnemySystem` 朝下一拐点继续通过 `Rigidbody2D.MovePosition` 移动。
4. 地图区块加载、卸载或重建后，延迟一次重建 NavMesh；不在每帧构建。
5. 敌人互相拥挤仍由局部分离处理；普通敌人离开活动区块范围时回收到对象池，持久敌人预留例外。

**验收**：敌人沿连续路径绕开墙体；不会出现方格直角走位；无路径或卡住时不会持续顶墙。

**依赖**：任务 4。

### 任务 6：地图 Seed 存档与恢复

**目的**：保证退出、继续游戏、卸载和重新加载始终重建同一张基础地图。

**快照扩展**：

- `WorldSeed`、固定 `ThemeId`、`GeneratorVersion`。
- 后续模块拥有的持久实体 ID 和状态由各自系统保存，不复制到地图核心。

**恢复顺序**：先恢复 Seed/主题/版本和玩家位置，再加载附近区块并重建基础 `MapChunkData`。

**验收**：同一对局继续游戏后，玩家附近的地形与阻挡物布局保持一致。

**依赖**：任务 3。

### 任务 7：地图对外查询、事件与实体锚点接口

**目的**：为后续模块提供稳定接口，但不实现它们的业务玩法。

**提供接口**：

- 查询世界坐标所属区块、`MapCellFlags` 和可通行状态。
- 查询或订阅区块加载、卸载、阻挡变化事件。
- 为确定性生成的静态实体提供稳定 `WorldEntityId`。

**明确不实现**：

- `ItemSystem` 的掉落与拾取。
- `MapEventSystem` 的区域击杀、奖励与进度。
- `WorldGuideSystem` 的屏幕边缘箭头。

**验收**：外部系统不需要访问 `MapChunkView`、Tilemap 或对象池即可读取世界状态。

**依赖**：任务 0、任务 3、任务 6。

### 任务 8：性能、稳定性与生成回归测试

**目的**：确保无限地图不会因加载、对象池或随机生成导致卡顿、泄漏和不可玩布局。

**内容**：

- 固定每帧加载/卸载预算与初始预热预算。
- 区块、装饰、阻挡 Prefab 的对象池失效引用清理。
- 多 Seed 自动封闭检测、跨区块一致性测试和存档重建测试。
- 活动区块、导航格数量、生成耗时的开发期统计。

**验收**：长距离移动时无持续对象增长；区块回收后可安全复用；生成测试不出现封闭或断路布局。

**依赖**：任务 3 至任务 7。

## 执行顺序

```text
任务 0 → 任务 1 → 任务 2 → 任务 3 → 任务 4 → 任务 5 → 任务 6 → 任务 7 → 任务 8
```

任务 7 的道具、事件、箭头功能不在本地图计划内，等地图接口稳定后分别立项。

## 任务 1 实施记录（2026-08-21）

- `MapSystem` 已使用 `WorldSeed + GeneratorVersion + ChunkCoordinate` 生成每区块固定的八个障碍投放结果。
- 出生点九宫格被永久排除；模板权重、占用格、最小间距、旋转和镜像配置均已参与结果生成。
- `MapChunkView` 已将投放数据写入 `ObstacleTilemap`；复用区块会先清空障碍 Tile。
- 现有 `TilemapCollider2D + CompositeCollider2D + Static Rigidbody2D` 负责阻挡玩家与敌人；投射物命中障碍 Tilemap Collider 时回收，爆炸投射物则在撞墙点触发爆炸。
- 防封闭 Flood Fill 校验尚未实现，保留为任务 2；因此当前只保证出生安全区与单模板间距，不保证复杂障碍组合的全局连通性。

## 任务 4 实施记录（2026-08-21）

- `MapChunkRoot` 已拆分为 `GroundTilemap`、`DecorationTilemap`、`MoveBlockerTilemap` 和 `ProjectileBlockerTilemap`。
- `DecorationTilemap` 只负责视觉；两个阻挡 Tilemap 使用独立的静态复合碰撞体，阻挡层渲染器由 `MapChunkView` 关闭，避免重复显示。
- `MapObstacleTemplateConfig` 新增 `BlocksMovement` 与 `BlocksProjectile`，模板可分别控制移动和投射物阻挡。
- 玩家和敌人只检测 `MoveBlockerTilemap`，投射物只检测 `ProjectileBlockerTilemap`。
- 地图生成将障碍占用与移动连通性分开计算，投射物专用障碍不会错误破坏移动 Flood Fill。

## 任务 5 实施记录（2026-08-21）

- 方格 `MapNavigationSystem` / BFS 流场方案已废弃，不再兼容。
- 新增 `MapNavMeshSystem`，使用 NavMeshPlus 生成运行期 2D NavMesh；敌人按需 A* 并缓存路径拐点，仍由 Rigidbody2D 驱动实际移动。
- 敌人生成先采样可行走 NavMesh，再检查 MoveBlocker 物理重叠；区块变化使 NavMesh 标记为脏并节流重建。
- Unity 包解析受当前代理 TLS 证书错误阻塞，待编辑器成功导入 Git 依赖后进行编译与 Play Mode 验证。
- 普通敌人离开导航窗口后回收到 `EnemyFactory` 对象池；持久敌人通过 `EnemyConfig.IsPersistent` 预留接口，不参与本次回收。
- 地图 Flood Fill 已强化为所有可通行格必须属于同一连通分量，避免敌人处于玩家不可达区域。
