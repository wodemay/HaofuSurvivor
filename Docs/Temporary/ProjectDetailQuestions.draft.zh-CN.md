# ProjectSurvivor 细节确认清单

> 临时设计文档。每个条目记录当前基线方案；具体数值允许在测试后调整。确认前不实现对应功能。

## 一、存档校验与恢复

已确认：使用明文 UTF-8 JSON，不做加密；保留结构校验、字段校验、版本迁移、`.bak` 备份和原子替换。

当前基线方案：

- 主存档与备份都损坏：分别重命名为带时间戳的 `.corrupt-*` 文件，创建默认存档，并提示玩家。
- 损坏原因：写入游戏目录 `Logs/save-recovery.log`，记录时间、文件类型、失败阶段、错误分类、简短原因和处理结果。
- 高版本存档：拒绝读取，不标记损坏、不创建空存档，保留原文件并停留在主菜单。
- 低版本存档：按连续迁移链升级，迁移成功后保存当前结构版本。
- 保存顺序：先写 Profile，成功后清理局内快照；快照清理失败不得重复结算。
- 校验失败范围：结构或单个字段无效时整份文件判定不可用，不跳过字段，避免生成半可信数据。

## 二、Profile 生命周期

当前基线方案：

- `GameStart` 初始化 `GameArchitecture` 后立即加载 Profile，再打开主菜单。
- Profile 不存在时创建 `ProfileCoin = 0` 的默认数据并立即保存。
- Profile 加载失败但已成功创建默认档时，提示玩家后进入主菜单。
- Profile 保存失败时保留内存数据和旧文件，不阻止普通游玩；主动退出、结算和场景切换时进入重试/退出流程。
- Profile 只由 `ProfileSystem` 和 `ProfileStorage` 访问，其他模块通过 Model、Command、Query 交互。

## 三、局内快照恢复

当前基线方案：

- 恢复顺序：读取并校验快照 → 恢复地图身份与数据 → 加载玩家附近区块 → 创建玩家 → 恢复玩家状态和装备 → 恢复实体数据 → 注册攻击与 Tick → 恢复保存时的 `RunPhase`。
- 玩家位置无效时，优先回退到最近可通行点；找不到时使用出生点并记录警告。
- 敌人、投射物、经验球、道具和持续效果全部恢复；实体位置无效时跳过单个实体并记录原因，不判定整份快照损坏。
- 未加载区块中的实体先保留为数据，不立即创建 View；进入加载范围后再实例化。
- 快照处于暂停或升级选择时，恢复对应阶段且不提前推进玩法 Tick；结算和死亡快照不允许继续游戏。
- 恢复完成前保持加载遮罩，所有核心数据校验通过后才进入可操作状态。

## 四、金币经济

当前基线方案：

- 普通击杀、Boss 击杀、存活时间、胜利和无尽轮次都使用独立配置项。
- 结算公式使用整数金币，最终结果统一向下取整，避免浮点误差产生额外金币。
- 普通模式以“单局平均可获得金币”作为基准，再反推局外升级价格。
- 局外升级价格采用递增曲线，并为每项升级设置等级上限；价格和效果写入配置，不写死在 UI 或结算代码。
- 无尽模式敌人属性不设设计上限，金币仍按存活时间、击杀数和 Boss 击杀数结算，不直接绑定敌人属性。
- 所有金币来源和消费都写入可查询的结算记录，便于平衡和排查。

## 五、无尽模式

当前基线方案：

- 一轮由若干敌人阶段和一个 Boss 结束点组成，Boss 被击败后立即进入下一轮。
- 轮次、阶段和 Boss 状态写入快照。
- 敌人数量、生命、速度、伤害分别使用独立且无上限的增长曲线。
- 前 10 轮缓慢增长，10～30 轮稳定增长，30 轮以后持续加速，确保停止移动或输出后最终无法挂机。
- 只保留 `NaN`、`Infinity` 和数值溢出检测，不作为游戏平衡上限。
- Boss 配置使用与普通模式相同的基础表，通过轮次倍率调整；不为无尽模式复制一套配置。
- 死亡和主动结算都记录当前轮次、Boss 击杀数和存活时间。

## 六、道具与可破坏物

当前基线方案：

- 道具掉落由独立 DropTable 配置，至少包含金币、百分比回血、全场经验吸收三类。
- 每个可破坏物每次只生成一个道具；掉落结果由权重抽取。
- 道具生成实体后按吸附逻辑飞向玩家，飞行过程不受障碍物阻挡，避免道具卡在墙后。
- 可破坏物使用独立运行时生命值，受到有效攻击累计三次后销毁；同一攻击实例对同一帧只计数一次。
- 可破坏物状态以稳定 ID 写入地图数据；销毁后区块重载不再生成。
- 可破坏物不设置全局数量上限，只限制每区块生成数量和最小间距。
- 可破坏物进入通用目标查询，但敌人不会将其作为攻击目标。

## 七、地图事件与指示箭头

当前基线方案：

- 第一版事件分为一次性事件和可按轮次重置事件，配置中明确类型。
- 状态统一为未开始、进行中、完成、失败四种；状态和进度写入地图数据。
- 离开触发区域后暂停进度，不重置已完成的击杀或计时。
- 事件目标离开加载范围后仍由数据状态继续统计，不能依赖实体是否存在。
- 每个未完成事件都显示独立指示器；箭头默认指向事件中心，完成后切换为奖励位置，奖励领取后隐藏。
- 多个事件同时存在时全部显示，不按优先级隐藏；指示器允许重叠。
- 指示器距离玩家越远尺寸越小，缩放到配置的最小尺寸后不再缩小。
- 指示器视觉结构固定为箭头底图加中心 Icon，Icon 由事件配置指定。

## 八、升级候选池

当前基线方案：

- 候选固定三个；候选类型允许同屏重复，但同一武器只允许出现一条当前升级路线。
- 武器、属性、闪避、角色专属升级分别配置权重；角色专属升级权重略高于普通属性。
- 已满级项目完全排除；没有可升级项目时才生成金币或回血等替代选项。
- 进化候选满足条件后进入高权重候选池，但不是必定出现。
- 组合武器生成后立即移除参与武器的运行时槽位和候选资格。
- 角色专属技能升级一次后从候选池永久移除；专属升级不占用武器和属性槽位。
- 候选生成失败时重新生成；确认失败不改变当前等级和槽位状态。

## 九、模块失败隔离

当前基线方案：

- 核心模块：启动、Run 生命周期、玩家生成、基础输入、基础战斗、生命、经验和核心地图通行。
- 可选能力：角色专属技能、地图事件、可破坏物、功能性道具、表现特效和非必要指示 UI。
- 核心配置缺失：终止当前对局创建，释放已创建对象并显示可诊断错误。
- 可选配置缺失：禁用对应能力，记录错误，其他模块继续运行。
- 可选系统初始化失败：不返回半初始化对象，不重复注册 Tick、事件、攻击或对象池。
- 每个模块必须定义启用状态、失败日志等级、清理路径和手动验收项。

## 建议执行顺序

1. 存档校验、迁移、备份和原子保存。
2. Profile 生命周期。
3. 局内快照恢复补全。
4. 金币经济配置与结算。
5. 无尽模式。
6. 道具与可破坏物。
7. 地图事件与指示箭头。
8. 升级候选池扩展。
9. 模块失败隔离验收表。
