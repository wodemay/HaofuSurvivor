# 局外金币、功能性道具与可破坏物体设计草案

本文记录目前已经确认的设计，不代表代码已经实现。后续实现必须继续按照 `Docs/DevelopmentPipeline.zh-CN.md` 逐项确认、拆分和验证。

## 一、金币分层

项目第一版只有一种永久资源：金币。

```text
RunCoin      本局临时金币，随本局快照保存
ProfileCoin  局外永久金币，用于局外升级
```

局内拾取只增加 `RunCoin`。死亡、胜利或主动返回并确认结算时，按照结算公式把本局金币转入 `ProfileCoin`。

主动返回有两种结果：

- 结算本局：结算金币、清理当前对局快照、进入结算界面或返回主菜单。
- 不结算：不增加 `ProfileCoin`，保留快照并返回主菜单。

主菜单存在旧存档时开始新游戏，也必须询问是否结算旧对局；确认后才清理旧快照并创建新对局。

死亡和胜利不询问是否结算，直接结算并显示结算界面。

## 二、金币结算

普通关卡的基础公式为：

```text
获得金币
= 基础奖励
+ 存活时间 × 时间倍率
+ 普通敌人击杀数量 × 击杀倍率
+ Boss 击杀数量 × Boss 奖励
+ 胜利奖励
```

第一版结算界面只显示：

- 存活时间。
- 击杀数量。
- 本局获得金币。

普通关卡只有一个最终 Boss。时间线负责推进敌人阶段和 Boss 出现，击败最终 Boss 后才触发胜利。

普通模式和无尽模式使用同一套 Boss 击杀金币配置。

无尽模式规则：

```text
阶段推进
→ Boss 出现
→ 击败 Boss
→ 进入下一轮
```

敌人数量和属性按轮次算法持续增长，不设置设计上的属性上限。无尽模式没有胜利奖励，死亡或主动确认结算时按照存活时间、普通击杀数量和 Boss 击杀数量结算金币。

所有金币数值必须进入配置和经济平衡表，统一考虑：

- 单局平均金币获取量。
- 普通敌人击杀收益。
- Boss 收益。
- 存活时间收益。
- 胜利收益。
- 局外升级和解锁消费。

## 三、存档校验与恢复

局内数据和局外数据分开保存，但都由 Save 层统一序列化、校验和恢复：

- `RunCoin` 写入局内快照。
- `ProfileCoin` 写入局外 Profile 存档。
- 不使用加密，不限制玩家修改单机存档。
- 保存数据使用明文 UTF-8 JSON，便于调试、迁移和人工修复。
- 通过结构校验、字段合法性校验和 `SaveVersion` 迁移保证可读性。

## 四、可破坏物体

### 生成

可破坏物体由独立系统管理，不复用敌人的生命和生命周期系统。

- 每个地图区块少量随机生成。
- 位置由地图种子决定，区块重载后保持一致。
- 不设置全局总数量上限。
- 使用最小间距限制。
- 不得与地图阻挡物重叠。
- 不得被阻挡物完全包围。
- 不得生成在玩家出生点或不安全区域。
- 新开一局使用新地图种子并重新生成。

配置只描述内容，不描述固定位置：

- 物体图片。
- 碰撞体参数。
- 最大生命值。
- 掉落表引用。

### 战斗目标

可破坏物体不是敌人，但必须接入通用目标查询，和敌人使用相同的最近目标规则：

```text
玩家攻击
  -> 最近目标查询
  -> 敌人或可破坏物体
  -> AttackSystem
  -> DamageSystem
```

玩家的自动攻击、投射物、范围攻击、穿透攻击、爆炸攻击和角色技能都可以命中可破坏物体。敌人的攻击不会索敌、命中或破坏可破坏物体。

### 生命与破坏

- 第一版固定承受 3 次有效玩家攻击。
- 第 3 次攻击后立即破坏。
- 关闭实体碰撞体。
- 标记地图状态为已破坏。
- 生成一个掉落物。
- 进入对象池。

实体碰撞体必须：

- 阻挡玩家。
- 阻挡敌人。
- 阻挡所有人的投射物。
- 不因敌人碰撞而损坏。

### 掉落

可破坏物体和敌人使用不同的掉落表。

可破坏物体每次只抽取一个功能性掉落，第一版包括：

- 按最大生命值百分比恢复的回血道具。
- 金币。
- 吸收全场经验的功能性道具。

掉落表使用可配置权重，不把掉落概率写死在代码里。

## 五、通用拾取逻辑

经验球、金币和功能性道具共用吸附逻辑：

1. 进入玩家吸收范围。
2. 锁定玩家。
3. 使用加速度飞向玩家。
4. 实际到达玩家位置后触发效果。
5. 执行完成后销毁或回收到对象池。

回血道具到达玩家后立即生效，即使玩家满血也正常吸收和消耗：

```text
恢复量 = 最大生命值 × 道具百分比 × RecoveryEfficiency
最终生命值 = Min(当前生命值 + 恢复量, 最大生命值)
```

`RecoveryEfficiency` 只影响恢复类道具。

吸收全场经验道具的流程：

- 读取当前对局中所有未收集经验球数据。
- 屏幕内和屏幕外经验统一标记为吸附。
- 未加载区块的经验通过异步队列分批生成实体。
- 每个经验球实际飞到玩家位置后才增加经验。
- 每帧生成数量上限通过性能测试确定，并保留为配置项。

## 六、Profile 存档结构

第一版 Profile 只保存：

```text
SaveVersion
ProfileCoin
```

实际文件位于游戏当前目录：

```text
SaveData/profile.json
SaveData/profile.json.bak
```

解密后的业务数据示例：

```json
{
  "SaveVersion": 1,
  "ProfileCoin": "123456789"
}
```

ProfileCoin 使用不可变 `BigCoin`：

- 非负整数。
- 内部使用分段数据进行大数运算。
- 最多 256 位十进制数字。
- 存档使用十进制字符串，不保存分段数组。
- 禁止前导零，`0` 是唯一合法零值。
- `AddCoins(BigCoin)` 和 `TrySpendCoins(BigCoin)` 是唯一变更接口。
- 余额不足时消费失败且不修改数据。

显示规则与实际数值分离：

- `万`、`亿`、`兆`以内使用中文单位。
- 超过 `兆` 使用科学计数法。
- 最多保留两位小数。
- 直接截断，不四舍五入。
- 去除末尾多余的零，例如 `1万`、`1.2万`、`1.25万`。

## 七、Profile 加载、迁移与保存

Profile 由 `GameArchitecture` 初始化时加载，`ProfileModel` 是唯一运行时状态，其他模块不能直接读写文件。

加载顺序：

1. 检查游戏根目录和 `SaveData` 路径。
2. `profile.json` 存在时读取明文 JSON，并验证结构与字段。
3. 文件不存在时创建 `ProfileCoin = 0` 的默认存档。
4. 旧 `SaveVersion` 按顺序执行迁移，例如 `v1 -> v2 -> v3`。
5. 数据结构没有变化时不增加 `SaveVersion`。
6. 迁移成功后写入当前结构版本。
7. 版本高于当前程序版本时拒绝读取并保留原文件。

损坏恢复顺序：

```text
profile.json
  -> 解密或校验失败
  -> 尝试 profile.json.bak
  -> 备份成功：恢复为新的 profile.json
-> 备份失败：标记 profile.json.corrupt-时间戳
  -> 创建 0 金币新存档
```

主存档和备份完全损坏时，分别重命名为带时间戳的 `.corrupt-*` 文件。损坏原因写入游戏目录下的 `Logs/save-recovery.log`，记录时间、文件类型、失败阶段、错误分类、简短原因和是否创建新存档。创建新存档后提示玩家，但不阻止进入主菜单。

存档版本高于当前程序版本时拒绝读取，不标记为损坏，不创建空存档，保留原文件并停留在主菜单。

玩家必须确认“存档损坏，已创建新的存档”提示后才能进入主菜单。损坏文件和备份都保留，不覆盖、不删除。

每次 Profile 数据变化都进入异步串行保存队列：

1. 将旧 `profile.json` 更新为 `.bak`。
2. 写入 `profile.json.tmp`。
3. 校验临时 JSON 的结构和字段。
4. 原子替换正式文件。

后台保存失败时自动重试 3 次，不暂停游戏、不弹窗，只保留内存状态并记录错误。玩家直接关闭游戏时不阻止退出，保留上一次成功的存档。主动退出、场景切换或结算时，保存失败才进入重试/退出处理。

Profile 与局内快照共用明文 JSON 存储与校验流程，不再使用 `SaveCrypto`、AES、HMAC 或密钥文件。

## 八、通用弹窗与保存提示

需要一个架构内单例式通用弹窗服务，由 `GameArchitecture` 或对应 System 统一管理。管理员负责创建弹窗 Prefab、按钮 Prefab、层级和 Bind，代码只接入参数和回调。

弹窗参数包括：

- 标题。
- 内容。
- 最多两个按钮的文本和回调。

空内容、空标题或空按钮文本对应区域不显示；两个按钮都为空时不显示弹窗。多个请求按 FIFO 排队，当前弹窗关闭后显示下一个。

弹窗打开时：

- 对局内保存当前精确 `RunPhase` 并暂停游戏逻辑。
- 关闭后恢复打开前的精确阶段。
- 非对局状态不修改 `RunPhase`。
- 队列未清空前保持暂停。

保存失败处理：

- 后台自动保存失败：不显示弹窗，静默重试。
- 主动退出、返回、场景切换或结算保存失败：关闭 `UILoadingOverlay` 后显示“重试 / 退出”。
- 重试：重新显示加载遮罩并执行完整保存。
- 退出：保留最近一次有效 Profile 和快照，放弃本次未保存变更，继续退出或切换。

`UILoadingOverlay` 只用于存档读取、主动流程保存和场景切换；局内后台保存不能显示它。
